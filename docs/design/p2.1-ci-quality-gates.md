# P2.1 CI and PR quality gates

## Objective

Make the repository's delivery contract executable on every pull request while
keeping Gentle-AI as the operational authority. CI validates this harness; it
does not replace Gentle-AI runtime checks or claim successful agent execution.

## Invariant

No pull request is merge-ready when the harness cannot be type-checked,
tested, packaged, or traced to an approved issue with exactly one `type:*`
label.

## Gate layers

| Gate | Evidence | Failure behavior |
|---|---|---|
| Repository integrity | Checkout succeeds and the working tree is the candidate commit | Stop; do not infer a result from a partial checkout |
| Node quality | `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm test` | Required check failure |
| Package contract | `pnpm pack --dry-run` and a package-content assertion | Required check failure |
| Gentle-AI read-only readiness | `gentle-ai version`, `gentle-ai sync --dry-run`, `gentle-ai doctor` | Report external/runtime blockers; never mutate managed assets |
| PR governance | Body links `Closes #N`; linked issue has `status:approved`; PR has exactly one `type:*` label | Required check failure |

## Workflow boundaries

1. `quality.yml` runs on `pull_request` and `push` to the repository's default
   branch. It installs only from the lockfile and executes the Node quality
   gates.
2. `gentle-ai-readiness.yml` runs the read-only ecosystem commands. A runtime
   or external-access limitation is surfaced as an artifact and annotation;
   it must not be converted into a fabricated success.
3. `pr-policy.yml` validates issue linkage and labels through the GitHub API.
   It uses the repository token with least privilege and never prints token or
   repository-private values.

The first implementation slice may combine the workflows only when each gate
remains independently named and reviewable. A future split is preferred if a
workflow exceeds the review budget.

## Trust and security

- Pin third-party actions to immutable commit SHAs before enabling them.
- Use `pnpm --frozen-lockfile`; do not run install scripts from untrusted PR
  content without an explicit policy decision.
- Use `permissions: contents: read` by default. PR metadata checks receive only
  the minimum pull-request and issues read permissions required.
- Upload reports as artifacts without environment values, home paths, tokens,
  or private project names.
- CI is evidence for the candidate commit only; it is not a substitute for a
  human review or a Gentle-AI receipt.

## Out of scope

Release publication, automatic merges, credential provisioning, runtime
foreground journeys, and Stitch/Impeccable UI orchestration belong to the
other P2 workstreams.
