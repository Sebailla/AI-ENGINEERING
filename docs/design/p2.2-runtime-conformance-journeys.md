# P2.2 Runtime conformance journeys

## Objective

Prove the projected Gentle-AI system prompt and adapter contract in each
supported client without confusing configuration detection with a real runtime
execution.

## Evidence boundary

The harness has two evidence levels:

1. **Static readiness**: files, managed asset versions, declared MCP servers,
   and canonical source links are detected by `doctor` and `conformance`.
2. **Foreground journey**: the named client is launched with a bounded prompt,
   the client reports the projected system prompt, and the expected MCP or
   orchestration boundary is observed. Only this level proves runtime behavior.

An absent client, unavailable MCP, authentication failure, or unsupported
foreground capture is `NO_VERIFICADO`, never `VERIFICADO`.

## Journey contract

Each journey records:

| Field | Requirement |
|---|---|
| Runtime | One of `codex`, `claude-code`, `opencode`, `pi`. |
| Entry | Exact executable and arguments, with secrets omitted. |
| Prompt | A deterministic probe that asks the client to identify the active authority and stop. |
| Expected evidence | A bounded transcript or structured runtime output proving the projected policy. |
| Negative control | A missing/stale adapter or MCP boundary that must not be reported as success. |
| Cleanup | Process termination and removal of temporary project state. |
| Result | `VERIFICADO`, `NO_VERIFICADO`, or `FALLIDO`, with command and evidence. |

## Initial journey matrix

| Runtime | Positive probe | Negative control |
|---|---|---|
| Codex | Foreground session identifies Gentle-AI as authority and loads canonical sources. | Hide Codex adapter; the probe must become `NO_VERIFICADO`. |
| Claude Code | Foreground session identifies the projected system prompt and returns without delegation. | Remove the projection; no success may be inferred from the executable alone. |
| OpenCode | `gentle-orchestrator` agent reports the authority contract and declared MCP boundary. | Start without the workspace adapter; readiness must remain unverified. |
| Pi | Foreground agent reports the persona/system prompt and adapter contract. | Omit `.pi` configuration; the journey must fail closed. |

## Runner design

- Journeys run against an isolated temporary project containing only canonical
  sources and the adapter fixture under test.
- The runner captures stdout/stderr and exit status, redacts home paths and
  credentials, and applies a timeout.
- The runner never writes user configuration or updates Gentle-AI assets.
- Each result stores the exact candidate commit, runtime, command shape,
  scenario, and evidence classification.
- A client that cannot expose its system prompt is reported as unsupported;
  a synthetic echo or file read is not a runtime proof.

## Implementation slices

1. Add a runtime journey interface and deterministic redaction helpers.
2. Implement one foreground adapter at a time, beginning with the client that
   exposes a stable noninteractive probe.
3. Add negative controls before expanding the matrix.
4. Publish a verification report with positive, unsupported, and failed counts.

## Out of scope

Provider quality, model correctness, interactive UI workflows, Stitch,
Impeccable, and release publication are separate concerns. This work proves
the harness/runtime boundary only.
