# P2.3 Stitch to Impeccable UI workflow

## Objective

Make UI generation a human-confirmed, auditable workflow: the agent sends a
Stitch prompt, waits for the client to explicitly report completion, applies the
approved output, and runs an Impeccable audit before delivery.

## Authority and blocking rule

Gentle-AI remains the orchestrator. Stitch and Impeccable are external
capabilities invoked through their declared MCP boundaries. The agent MUST NOT
infer that Stitch finished from elapsed time, a successful request, a file
appearing on disk, or a provider response that lacks the client completion
signal.

## State machine

```text
READY
  -> PROMPT_DISPATCHED
  -> AWAITING_CLIENT_CONFIRMATION
  -> CLIENT_CONFIRMED
  -> APPLYING
  -> APPLIED
  -> AUDITING
  -> AUDITED
  -> DELIVERY_READY
```

Any missing MCP server, malformed response, timeout, declined confirmation or
failed audit transitions to `BLOCKED` and preserves the previous UI state.

## Typed contract

| State | Required evidence | Allowed next action |
|---|---|---|
| `PROMPT_DISPATCHED` | Sanitized prompt ID and Stitch request receipt | Wait only |
| `AWAITING_CLIENT_CONFIRMATION` | Client-facing completion question and exact allowed answer | Stop and wait |
| `CLIENT_CONFIRMED` | Explicit confirmation bound to the prompt ID | Prepare isolated apply |
| `APPLIED` | Changed-file manifest, digest and rollback snapshot | Start audit |
| `AUDITED` | Impeccable result, version and artifact references | Evaluate delivery gate |
| `BLOCKED` | Reason code, preserved state and remediation | No apply or delivery |

The confirmation is single-use and candidate-bound. A confirmation for a
different prompt, project or UI revision is invalid. No credentials or raw MCP
payloads are stored in the receipt.

## Apply and rollback

- Apply only inside an isolated worktree or UI-owned edit root.
- Record the before/after manifest and content digests.
- Keep generated assets separate from hand-authored UI until confirmation and
  audit pass.
- Roll back only the candidate-owned files when apply or audit fails.
- Never mutate Stitch or Impeccable managed configuration from this harness.

## Audit contract

Impeccable must receive the applied candidate identity, not an uncommitted
working tree. The audit result is `VERIFICADO` only when it includes the
candidate revision, audit status, findings and remediation state. A missing
Impeccable MCP server is `NO_VERIFICADO`, not a clean audit.

## Current evidence and next slice

No Stitch or Impeccable MCP tool is available in the current runtime context.
This discovery therefore defines the contract only. The implementation slice
must add typed state transitions, a blocking confirmation adapter and negative
controls before any UI output can be applied.

## Out of scope

Design generation quality, provider billing, credentials, visual taste and
automatic human approval remain outside this harness contract.
